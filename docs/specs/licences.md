# Licences

Part of the [architecture overview](../architecture.md).

- **The app** (`src-tauri/src/licence/`, docs/licensing.md, The app): Rust parses and verifies a key exactly as docs/licensing.md (Formats) says, with `ed25519-dalek` (`verify_strict`), against the public keys the build holds by `kid` (`licence/keys.rs`: a committed table of production keys (kid `2026-10` since v1.0.5-beta1); the test vectors' `test` key in test and debug builds only).
  The key lives in the keychain (a generic password under the app's identifier, account `license`, beside the AI keys), read once per run; a read the keychain refuses shows `E_LICENCE_KEYCHAIN` (`E_LICENCE_KEYCHAIN_DENIED`, with what to do, for a refused access prompt), leaves the item as it is and is tried again at the next tick rather than at each write, each of which would prompt again.
  The state is none, valid (in every version: nothing in a key ends), revoked (the ID is in the last verified revocation list, kept in `<app data>/license-revocations.txt` and verified again on every read; an older list never replaces a newer one) or invalid (with `E_LICENCE_MALFORMED`, `E_LICENCE_UNKNOWN_KID` or `E_LICENCE_SIGNATURE`).
  Until the build holds a production key nothing is gated, the trial never starts and the keychain is not even read to say so.
  - **The trial** (`licence/trial.rs`): the first launch of a build with a production key begins a 30-day trial, also on a device that used an ungated build before.
    Its start and the latest time seen are one keychain item beside the license (account `trial`, JSON `{start, seen, ended}` in milliseconds), which outlives a reinstall.
    It runs while `start <= now < start + 30 days` and `now` is not more than an hour before the latest time seen.
    A clock set back further ends it for good (`ended`, written at once, `W_TRIAL_CLOCK_SET_BACK`).
    The latest time seen is written at launch and every 10 minutes (not while a license is valid; a write the keychain refuses waits the 10 minutes too, as each may bring back its prompt) by a thread that looks at the trial every minute (`License::tick`) and sends `devot://license-changed` when what the windows show changed (the trial ended); it is not written on writes.
    An item the keychain cannot give, or one that does not parse, counts as ended (`W_TRIAL_UNREADABLE <code>`, read again at the next tick); a damaged item never begins a new trial.
    A valid license overrides the trial.
    The iPhone's Settings screen and tab badge count the trial's days by a clock read again when the app returns to the foreground and when the count next drops (`phone/licenceClock.ts`).
    With the native screens the iPhone's License page is native (`UI/Settings/LicencePane.swift`): it reads and changes the licence through `direct.licence.*`, the bodies of the commands above, and shows what the page's License pane shows, with the key field only where the build takes keys and Remove behind a confirmation.
    The native Settings reads the licence again each time its root shows and when the app comes back to the foreground, and its License row and the app row count the trial's days as the page does, moving on when the trial drops a day; the key never comes back from Rust.
  - **Commands:** `licence_get` (main, note, quick capture and Settings windows: gated, state, code, license ID, licensee, plan, and the trial's state, end and code; never the key), `licence_set(key)` (main and Settings: drops the spaces and line breaks a mail client wrapped the key in, verifies it and refuses one that fails with its code, changing nothing), `licence_remove` (Settings only) and `settings_open_licence` (main and note windows: Settings at its License pane, `settings.html?pane=license`, or `devot://settings-pane` to an open one).
    Every change goes to every window as `devot://license-changed`.
  - **Seats** (`licence/activation.rs`, `licence/device.rs`, `licence/client.rs`, docs/licensing.md, Activation): a release build gives `Licence` the keychain items `device` (16 random bytes, made once, never a hardware identifier) and `activation` (the signed lease plus the seats the Worker reported).
    Adding a key asks `https://licence.devot.online/activate` over `net::post` with the key in the body; the lease (`devot1dev.…`) is checked offline and must name the licence and this device.
    Writes need a live lease or the 30-day migration window a key added offline gets; a device offline past its lease is read-only until it reaches the Worker once.
    The daily schedule in `updates.rs` renews the lease within 7 days of its end, and `licence_refresh` (Settings) asks now.
    The `/devices` page frees a seat for a device the buyer no longer has.
  - **Request a Refund** (iPhone App Store builds, `licence/app_store.rs`, docs/licensing.md, App Store builds): Settings shows the row beside Get a Mac License Key while Devot Pro is held through the App Store.
    `store_refund` (the iPhone's main window only) takes no argument and asks StoreKit for a refund of the Devot Pro transaction the licence holds, through the Swift bridge's `devot_store_refund`, which opens Apple's sheet over the active `UIWindowScene`.
    Its outcome is requested or cancelled; Apple's decision arrives later as a revoked transaction update, so the command changes nothing the licence holds.
    The row shows plain sentences from the catalog, never a code, and the logs carry codes only, never the transaction.
  - **Enforcement:** with gating on, no valid license and the trial over, `SyncService` refuses to create a vault and to connect, and `Ai::generate` (the one path every AI request takes: edit proposals, next edit suggestions, every provider) refuses before it reads a key, all with `E_LICENCE_REQUIRED`, or `E_LICENCE_UNREADABLE` when the keychain would not give the license, the trial or the seat (any `E_LICENCE_KEYCHAIN*` read error), which adding a license would not fix; the item is read again at the next tick, so that code may clear on its own.
    A device that already syncs stops at its next connect: the engine treats both codes as ones that stop sync, and the main window starts the engine again when the license changes.
  - **Read-only:** every write of user content refuses with `E_LICENCE_REQUIRED` too.
    The database hands its store out shared for reads (`Db::call`) and exclusively only through `Db::write(kind, …)` and `Db::write_judged`, after the gate `License::require_write` (set at launch, `Db::guard`), so no write reaches SQLite another way: note bodies and metadata, revisions and their deletion and compaction, notebooks, tags, attachments and their copies, the Trash and purges, sync's incoming changes and purges, and restoring a backup.
    Imports, templates, quick capture, the local HTTP API and plugins all write through those commands.
    Kind `Body` (`note_put` of a note already stored, `note_put_meta`, `revision_put`, none of them out of the Trash) is still taken for five minutes after a trial ran out (not one the clock ended), a seat's lease ran out or a refund took Devot Pro, so a save in flight lands; kind `Bookkeeping` (sync's own state and reset, rebuilding the search index) is never refused.
    A note's first save (`note_put` of an ID with no row, trashed or purged, yet) is kind `Content`, so the grace never stores a new note.
    A save that brings a note back from the Trash (`note_put` or `note_put_meta` whose newer `deleted_hlc` clears `deleted_at`, `Store::restores_note`) is kind `Content` too, so the grace never restores a note; a save of a note in the Trash that leaves it there is still `Body`.
    `Db::write_judged` asks the gate for both `Body` and `Content` on the caller, before it queues the job, because a gate that misses its caches reads the keychain and would otherwise hold up every read and write behind it.
    The job then reads whether the row exists and whether the write restores it, in the same job as the insert, so no other write comes between the check and the put, and takes the answer for the kind it found.
    Kind `Welcome` (`welcome_seed`, the first-launch notes) is never refused either: the command takes only a clock stamp and a time, writes the copy of the notes the build bundles (`src-tauri/src/commands/welcome_seed.json`), and writes nothing once the library holds any note, any notebook but Templates, anything in the Trash, or a row with one of the notes' IDs, however deleted or purged.
    Quick capture (`quick_capture_save`) and the local HTTP API (its write routes, 403, or 503 for `E_LICENCE_UNREADABLE`) refuse before the main window is asked, since the core keeps an edit it could not save pending.
    Settings, window state, the license and the trial, making backups, exports and the Markdown mirror keep working.
  - **Windows:** while editing is not allowed (`useEditing`, `entitlements.has('editing')`, which also turns at the trial's end by the window's own clock), the editor is read-only (`EditorState.readOnly` and a change filter that lets only Yjs changes from other replicas through; no paste or drop; no format, table or image bars), the title, notebook, status and tags are read-only, the commands that change notes (`changesNotes` in the registry: formats, inserts, table edits and every command that makes, moves, tags or deletes) leave the window's shortcuts, menus and palette, context menu items that change notes are hidden (`edits` on a menu entry), rows are not dragged, New Note and New Notebook are disabled, the Trash's, a selection's, a version's and a backup's restore and delete are disabled, and quick capture keeps its draft and saves nothing.
    When the trial ends during a session the windows save what was typed (`flush`) as they turn read-only.
    One bar in the main and note windows says the trial has ended and notes are read-only, with Buy a License and Add License; nothing dismisses it.
    Once, when less than 24 hours are left, a notice says the trial ends today or tomorrow at its time, with the same buttons; Dismiss is kept (`devot.trial.reminded` in local storage, by the trial's end) and it never comes back.
    Dismissing it in one main window removes it from every open main window (the storage event).
  - **The iPhone:** every write it offers (a new note or notebook, trash, complete, pin, status, move, tags, the title, Edit, a task box and AI) goes through one gate, `requireEditing` (`phone/requireEditing.ts`), which decides from the licence snapshot and never tries the write.
    While editing is locked it shows one surface: in an App Store build that needs a purchase, the purchase sheet headed that Devot Pro is not active or that the trial has ended; otherwise the short Pro sheet, which asks for a key, sends a license or seat that needs attention to Settings > License, or offers Try Again while App Store purchases or the keychain could not be read.
    The gate keeps what was asked (the action and a note or notebook ID, never any text) and runs it through the gate again once the surface unlocks editing (Try Free, a purchase, Restore Purchases, Try Again).
    Not Now, closing the sheet, Enter License Key, Open License Settings, a tab switch, the app going to the background and ten minutes passing drop it, so nothing is written behind the user's back.
    When Rust refuses a write the snapshot allowed (`E_LICENCE_REQUIRED` or `E_LICENCE_UNREADABLE`), the phone logs `W_PHONE_WRITE_LOCKED op=<op> code=<code>`, reads the licence again and shows the surface, with nothing to continue; no surface shows a code.
    A locked note opens in Preview and stays there; the editor Find shows is read-only and takes no caret (`EditorView.editable` false), so a tap raises no keyboard.
    With the native screens a write a native screen starts (New Note so far) goes through Swift's `ProGate` instead (`UI/ProGate.swift`, docs/specs/iphone-screens.md, The gate), which shows the same surfaces natively (`UI/ProSheet.swift`, and `UI/Settings/PurchaseSheet.swift` with the gate's heading) and holds the intent by the same rules; `tests/fixtures/licence-gate.json` holds it and `requireEditing` to one table.
    Swift's licence snapshot is only the UI's guess, read again when the app becomes active and when Rust sends `licence.changed`; Rust's write gate stays the lock on every write, and a refusal pops the new note's screen before anything shows in it.
  - **Logs** carry codes and the license ID (`I_LICENCE_SET license=<id>`, `I_LICENCE_REMOVED`, `W_LICENCE_REFUSED <code>`, `I_LICENCE_REVOCATIONS issued=<at> count=<n>`); the key and the licensee never reach a log, an error or a `Debug` line, and a test checks it.
  - **Settings > License:** the state in a sentence, the trial's end and time left while it runs (or that it ended), licensed to and license ID; a field to add or replace a key, Remove License… (asks first), and Buy a License, which opens `https://licence.devot.online/buy` in the browser through `open_external` (the address is one constant, `LICENCE_SITE` in `src/renderer/src/licence.ts`).
    Settings > Sync and Settings > AI show a locked row with Buy while their feature is locked, saying the trial has ended when that is why; Edit with AI is not offered once the trial is over, and a refusal from Rust says a license is needed; a Suggest Next Edit key press says so in a notice (a pause asks nothing); the main window's sync notice says sync stopped for want of a license (the trial having ended), with Buy.
    `E_LICENCE_UNREADABLE` says instead that Devot could not read its license from the keychain, with no Buy, in the sync notice, Edit with AI, Suggest Next Edit, import and quick capture.
  - **Tests:** the Rust tests read `licence/test-vectors.json` and check every entry (valid keys, each invalid key's code, the list and its tampered copies), the malformed shapes, the states, gating both ways, the stored list, and AI and sync refusing with nothing sent (the sync test against the Node relay); the trial's states (fresh, running, ended, the clock set back, a later launch, a license over it, an ungated build, an unreadable item, the ten-minute write) and the write gate (`storage::db`, the HTTP API's writes, the trial's, seat's and refund's grace taking an existing note's save but not a new note's).
    `tests/core/entitlements.test.ts`, `tests/core/sync-licence.test.ts`, `src/renderer/src/licenceView.test.ts`, `src/renderer/src/TrialNotices.test.tsx`, the registry's and the menus' tests, `tests/ui/licence.spec.ts` (Settings > License, the locked features, the link) and `tests/ui/trial.spec.ts` (read-only mode, the bar, the reminder, the trial in Settings > License, quick capture) cover the windows.
- **License Worker** (`licence/`, docs/licensing.md, ADR 0006): a Cloudflare Worker on the owner's account with a D1 database, the one hosted service.
  It creates Stripe Checkout Sessions (Managed Payments, or Stripe Tax when a variable says so), issues one Ed25519-signed license key per paid session from the webhook or from the success page, whichever comes first, mails keys through Resend's HTTP API (a `fetch` call with an idempotency key; runs on Workers Free), mails them again on request (`/resend`, the same answer whatever the address, rate-limited), limits `/buy` to 10 Checkout Sessions an hour per IP (counted under a keyed hash as `/resend` counts, then 429 with `Retry-After` until the hour ends) and serves the signed list of licences revoked by a full refund or a lost dispute (`/revoked`).
  Its pages and email look like devot.online in light and dark, with the stylesheet and Copy script on fixed routes under a strict CSP (no inline script or style), `no-store`, `no-referrer` and no framing.
  D1 holds licences, purchases (Checkout Session, Customer and PaymentIntent IDs), refunded PaymentIntent IDs and rate-limit counters; no email address, no key and no notes.
  Stripe is a small `fetch` client with a pinned API version, the mailer and the store are interfaces, and the tests run every route on a real D1 database in workerd through Miniflare with Stripe and the mailer faked.
  The key and list formats, and the test vectors the app's Rust check reads (`licence/test-vectors.json`), are in docs/licensing.md.
  The app never imports the Worker.

- **Seats in the Worker** (ADR 0009): D1 holds one row per activated device (`activations`: licence ID, the app's random device ID, the label, when it was taken and last seen).
  `/activate` checks the key's signature against the current key and any older one in `LICENCE_KEYS`, refuses a revoked licence, activates a complimentary key with no row (the signature is the root of trust) and takes a seat only while the licence holds fewer than `MAX_DEVICES` (3); it answers with a 30-day `devot1dev.…` lease.
  Requests are counted per licence and device.
  `/deactivate` and the `/devices` page free a seat.
  No hardware identifier, address or machine name is stored, and the key travels in the request body.
  The app's `activation` item also lists every licence it has tried (32 at most), so a migration window cannot be restarted by pasting a key again or swapping keys; a seat item that cannot be read locks the device, and one that does not parse is replaced when the key is pasted again.
  A refusal from the Worker (any code but an unreachable one) ends that licence's migration window at once, whether the key was pasted or held from before seats.
  A pasted key the keychain will not store changes no seat: the licence held keeps its lease or window, and the new key is not counted as tried.
