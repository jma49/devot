# Extensions

Part of the [architecture overview](../architecture.md).

- An internal, versioned extension API.
  Built-in preview renderers (and their islands) register through it (`PREVIEW_API_VERSION`; see the preview section's Extension point); commands and keymaps have their own registry (`src/renderer/src/commands/`).
  Built-in features written against it so far: math, Mermaid, emoji, alerts, embeds and the other preview renderers.
  Import, export and themes are built-in code.
- **Third-party plugins** (ADR 0005, `PLUGIN_API_VERSION` 1) contribute commands, menu items, keymaps, preview renderers and import and export formats, each with a permission the user approves on install.
  No permission reaches the network, other notes, storage or Tauri.
  - **Package:** a folder with `devot-plugin.json` (ID, name, version, API version, optional `minAppVersion`, main script, permissions, contributions), or a `.zip` of one, at most 256 files and 20 MiB.
  - **Versions** (ADR 0020): API versions only add, and Devot runs every one from `PLUGIN_API_OLDEST` to `PLUGIN_API_VERSION` (1 through 3 now); a permission records the version that added it.
    A package for a newer API (`E_PLUGIN_API_TOO_NEW`) or a newer Devot than this one (`minAppVersion`, `E_PLUGIN_APP_TOO_OLD`) is refused before the approval sheet, and Settings says it needs a newer Devot; listing leaves out a plugin the app became too old for.
    Rust reads it whole and checks it (`src-tauri/src/plugins/`), the page checks the manifest again (`src/core/plugins/manifest.ts`); both run `tests/fixtures/plugins/manifests.json`.
  - **Install:** Settings > Plugins > Install from Folder or Install from Archive picks a package in a native panel; the sheet lists what it asks for, and Install approves it all (Cancel, which has the keyboard, installs nothing).
    Rust writes it to a new folder and renames it into `<app data>/plugins/<id>/`, replacing an older version whole, and records it as on with those permissions in `plugins.json` (granted permissions the manifest on disk no longer asks for do not count).
    The pane turns plugins on and off, lists their permissions and removes them.
    Nothing is downloaded; plugins never sync and backups leave them out.
  - **Official plugins** (ADR 0025): Settings > Plugins > Official Plugins lists the index on devot.online (`src-tauri/src/plugins/catalog.rs`) with Install, Update, Installed or Needs a Newer Devot; Install and Update fetch the listed archive, check its size and SHA-256, and show the same review; `devot://plugin/<id>` opens Settings at that review.
  - **Themes** (ADR 0026): a plugin with the `themes` permission lists color themes, files of `--color-*` token colors that Rust and the kit check (`E_PLUGIN_THEME_INVALID`); Settings > Appearance shows each such plugin as a card of its light and dark themes beside the built-in ones, where a card chooses its themes for both appearances and a swatch for one, a plugin theme takes the place of the built-in theme for its appearance (which goes back to Default), and every window sets its colors over the built-in tokens (`src/renderer/src/theme/pluginThemes.ts`).
    Icons keep Devot's colors under every theme: a theme's status marks (`status-*-mark`), settings tiles (`icon-tile-*`), tag icons (`tag-icon-*`) and phone status tiles (`phone-status-tile-*`) are left out, so a status or a pane reads the same in every theme.
    A theme's text and selection colors are raised to Devot's own contrast where they fall short, keeping their hue (ADR 0026), so no theme is harder to read than the default.
  - **Drawings** (ADR 0027, API version 2): a preview renderer with `output: "svg"` answers an SVG drawing for the theme on screen (appearance and diagram colours as hex); the page rebuilds it from a fixed list of SVG elements into a shadow root of its own, with no script, link, `foreignObject` or remote URL, and nothing drawn outside its box (`src/renderer/src/preview/pluginDrawing.ts`).
  - **Kept drawings** (ADR 0030): the main window keeps each drawing it shows with its note, rebuilt and serialized with its stylesheet in one `style` element, keyed by plugin ID, fence language, the block content's SHA-256 and appearance (`src/core/plugins/drawings.ts`).
    At most 256 KiB a drawing and 32 drawings or 1 MiB a note.
    A device whose plugin draws drops that plugin's drawings of blocks the note no longer holds when it keeps one and when it pushes a change made to the note there; other devices never drop any, so a block edited there keeps its note until a device with the plugin draws it again or pushes a change to the note.
    The drawings sync with the note, and a window without the plugin (the iPhone, a note window, a Mac without it or with it off) shows the kept drawing of a block in the preview while its content and the appearance match, rebuilt through the same allowlist (`keptDrawingIsland`), with no Edit button.
    A block with no matching drawing shows as code with a note that the drawing updates on a Mac with the plugin; exports and printing show plugin blocks as code.
    A note with a fence waits for its drawings before its first render, and a change another device or process makes draws the preview again only when the note's list changed (`src/renderer/src/preview/keptDrawings.ts`).
    The page bounds a blur's and a drop shadow's `stdDeviation` to 32 and a morphology's `radius` to 16, leaves out CSS `filter` and `backdrop-filter` declarations, in `style` attributes and elements, and keeps a `filter` attribute only when it names a filter by fragment.
    A note shown whose drawings could not be read is read again once after a second, then on each change to it; a change to one note's list draws again only that note's kept drawings (a revision per note).
  - **Editable drawings** (ADR 0029, API version 2): a drawn renderer with `editable: true` gives its drawing an Edit button where the note can be changed; `preview.edit` hands the plugin the block's content while it is active, and its answer goes back in the block's own fence as one undo step (`src/core/plugins/blockEdit.ts`), refused when the block changed meanwhile.
  - **Sandbox:** only the main window runs plugins.
    Each enabled plugin gets a hidden `<iframe sandbox="allow-scripts">` on `devot-plugin://localhost/<id>/`, which Rust serves for enabled plugins only: Devot's container page (`src-tauri/plugin-frame/`), which frames the plugin's page in another sandboxed frame and lets that one page load, so the plugin can never navigate.
    The plugin's page runs Devot's runtime, then the plugin's script, under `default-src 'none'` with scripts (and WebAssembly, `'wasm-unsafe-eval'`, never `eval`), styles, images, fonts and media from its own folder and every connection, frame, worker and form refused; WebRTC is off in every main and note window's web view (WebKit's `PeerConnectionEnabled` preference), as are resource hints (preconnect, preload, prefetch and DNS-prefetch), which would otherwise reach the network outside the policy; the runtime removes WebRTC too and refuses child frames and hint links (also through the `document.body` and table `caption`/`tHead`/`tFoot` setters), through DOM methods it keeps before the plugin's script runs.
    A preconnect connects synchronously on insertion, so the native preference is the guarantee and the runtime guard is defence in depth.
    Both frames have opaque origins, so a plugin shares no storage, cookies or DOM with the app or another plugin, and Tauri's IPC and invoke key are in the main frame only.
    The plugin's own files carry `Access-Control-Allow-Origin: *`, so its opaque-origin page can load them as modules and fonts, which are cross-origin requests that WebKit otherwise refuses; Devot's pages and scripts on the scheme do not.
    The main window's policy only gains `devot-plugin:` in `frame-src`.
  - **Protocol** (`src/core/plugins/protocol.ts`, version 1): the main window hands each frame a `MessagePort` and binds it to that plugin (`src/renderer/src/plugins/host.ts`).
    The newest plugin API is 3; API 1 and 2 plugins still run, but API 3 import result fields and manifest limits require a manifest declaring API 3.
    Plugins call `note.read`, `note.replace` (the text read and the new text; refused when the note changed since), `ui.show` and `ui.hide`, and from API version 2 `storage.get`, `storage.set`, `storage.delete`, `storage.keys`, `settings.get`, `notes.list`, `notes.search`, `notes.get`, `notebooks.list`, `note.selection` and `note.insert`; the host calls `command.run`, `preview.render`, `import.convert` and `export.convert`, and sends the events `ui.hidden`, `settings.changed` and `note.opened`.
    Every call is checked for its shape, a known method, its permission and, for the note and panel calls, that one of the plugin's commands is running or its panel is open; refusals and failures are answered and logged as codes with the plugin's ID.
    At most 64 calls wait per plugin; a plugin answers within 5 s (a drawing), 30 s (a conversion) or 60 s (a command).
  - **Own data and settings** (ADR 0021, API version 2): with `storage` a plugin keeps JSON values under its own keys (256 KiB a value, 1 MiB and 1000 keys a plugin), and the settings its manifest declares (`toggle`, `text`, `number`, `choice`) show under it in Settings > Plugins.
    Rust keeps both in `<app data>/plugin-data/<id>.json` (`src-tauri/src/plugins/storage.rs`), which an update keeps and removing the plugin deletes; Settings stores only a value that fits its declaration and emits `devot://plugin-settings-changed`, which the main windows pass on to the plugin.
  - **Other notes** (ADR 0022, API version 2): with `notes.read` a plugin lists, searches and reads live notes outside Templates and the Trash, and lists notebooks, at any time, through the core (`src/renderer/src/plugins/notes.ts`); it changes none of them.
  - **Note queries** (ADR 0028, API version 2): note summaries carry tag names, status and pinned, and `notes.get` carries the front matter as `properties`; while a plugin with `preview` and `notes.read` is enabled, plugin blocks are drawn again a second after the notes change (`src/renderer/src/plugins/libraryTurn.ts`).
  - **The selection** (ADR 0023, API version 2): while active, `note.selection` reads the editor's main selection and `note.insert` writes in its place as one undo step (`src/renderer/src/editor/pluginText.ts`), refused when the selection no longer holds the text the plugin read; `contributes.slashMenu` lists commands in the editor's slash menu under Plugins (`src/renderer/src/editor/slashPlugins.ts`); plugins with `notes.read` get `note.opened` with the open note's ID.
  - **Edits** go through the core as Yjs diffs (`NoteService.applyPluginEdit`, `textEdits`), with the text before kept as a version, and the editor applies the update as one undo step.
  - **Contributions:** commands in the palette under the plugin's name; a keymap's key works in the whole window when it is a valid shortcut with Command or Control that no app command, reserved key or earlier plugin (by ID) uses, and is dropped and logged otherwise; menu items in the Plugins menu, which Rust builds from the manifests (with Plugin Settings… last) and whose picks reach the window as `devot://plugin-action`; preview renderers draw fenced blocks of their language as Markdown the preview renders and sanitizes like note text, without plugin renderers, with a link to a note shown as a chip like one in the note's own text (a block without an answer stays code; exported and printed pages show it as code); import formats (File > Import and the palette) turn the files Rust reads from a native panel (UTF-8, 5 MiB each, 20 at a time) into notes in the notebook shown; export formats (File > Export and the palette) turn the open note into text Rust writes whole where the save panel says.
    Rust rebuilds these menu items on the main thread after an install, a removal, a plugin turned on or off and a licence change, and swaps their actions in one step, so a pick during a rebuild finds an action or nothing.
  - **UI:** a plugin shows its frame only from one of its commands (`ui.show`), in a sheet titled with its name, with Close; the frames stay in that sheet while it is closed, so showing one never reloads it.
    Closing tells the plugin (`ui.hidden`).
  - **Plugin kit** (ADR 0024): `plugin-kit/` holds the API's types and the `devot-plugin` command (`new`, `validate`, `pack`), bundled from the app's manifest rules (`pnpm plugin-kit:build`); its tests in `tests/plugin-kit/` keep it in step with the runtime and the package limits.
  - **Rich imports** (API 3): `import.convert` returns one converted note or an array of up to 5,000; an array imports into a notebook named after the file, while a single note keeps the previous destination behaviour.
    A converted note has a title and exactly one of `markdown` or `html`, optional tag names, nonnegative integer millisecond `createdAt` and `updatedAt`, attachments `{name, mime, data}` with base64 bytes, and diagnostic codes in `diagnostics`.
    The host validates the complete answer before writing, caps each body or HTML input at 32 MiB, each note's tags and attachments at 1,000, and the answer's text and base64 at 140 MiB together.
    Attachments use zero-based URLs `attachment:0`, `attachment:1` in images; the host decodes and checks their bytes, stores supported raster images up to 10 MiB with the note, and rewrites image URLs to the stored IDs.
    Unsupported or invalid attachments are skipped and listed by code in the import report, never logged with content; other plugin diagnostics must also be codes.
    An import that creates notes with only per-note diagnostics shows the imported-note and skipped-item counts, while converter errors or failures to create notes retain the failure notice.
    Show Skipped opens the import results sheet with each item's name, translated reason and a button to open its note; reports carry attachment names and note IDs and titles for display only, while logs retain codes and IDs only.
    HTML goes through the host's sanitized `htmlToMarkdown`, never directly into the note or the app's DOM.
    Tags are applied through the tag service and explicit dates through `setDates` after the body and tags, clamping Updated to Created when needed and using the current time for a missing date.
    The host reuses the core import pipeline's per-note progress, cancellation boundaries, error reporting and cleanup.
    An import format may declare `maxFileBytes` from 1 byte through 100 MiB in its API 3 manifest; Rust enforces it, defaulting to 5 MiB for formats without one.
    The first-party `.enex` export files converter lives in `plugins/enex/`, not in the core's import kinds; `pnpm plugin-enex:build` bundles its XML parser and conversion logic into its sandbox script.
  - **Tests:** `tests/ui/plugins-sandbox.spec.ts` (a hostile plugin cannot reach Tauri, the main window, another plugin, the network or a note without permission), `tests/ui/plugins.spec.ts` (each contribution point), `tests/ui/plugin-settings.spec.ts`, `tests/ui-csp/csp.spec.ts` (a plugin under the production policy), `src/renderer/src/plugins/host.test.ts`, `src/core/plugins/protocol.test.ts`, `tests/core/plugin-*.test.ts`, and Rust's `plugins` tests (packages, install, serving, menus).
    The UI tests serve the same pages from `src-tauri/plugin-frame/` (`tests/ui/plugins.ts`).
