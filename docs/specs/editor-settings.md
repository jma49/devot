# Editor settings

Part of the [architecture overview](../architecture.md).

- **What:** Settings > Editing and Settings > Preview (the Settings window has a 200 px navigation column, `size.settings-nav-width`, under a capsule search field, with a row and a coloured tile per pane: General, Editing, Preview, Appearance, Keyboard, Mirror, Sync, AI, License, Integrations, Plugins and Usage; Back and Forward share one capsule in its toolbar; each pane's sections have a 13 px semibold title above a card, an optional footnote under it, and each setting a label, a grey description and its capsule control on the right).
  Editing has three sections.
  Interface: the selection toolbar (on), line numbers, highlighting the active line (off), line wrapping (Off, All lines, Prose only, which keeps code blocks and tables on one line each, or Unwrap at cursor, the default, which does that only for the code block or table under the caret and keeps the caret's line in place on screen; code in a quote or an alert wraps with it; a stored on/off from an older Devot reads as Unwrap at cursor/Off), inline image widgets, a readable line width (`size.reading-width`, 740 px), scrolling past the end (on) and the cursor scroll margin (pixels, 0).
  Markdown: the unordered list bullet (`*`, `-` or `+`), the indent unit (2 or 4 spaces or a tab), tab size, how a lone pasted URL goes in (as copied, `<url>` or `[](url)`; see Pasting URLs) and spell checking (on).
  Text Appearance: font size (10 to 32 px; also Cmd+=, Cmd+- and Cmd+0 in the main window, the registry's `view.font*` commands), font family (System, SF Mono, Menlo, Monaco or Courier New), font weight (normal or 300 to 700), line height (1.2 to 2.0 offered, 1.0 to 2.5 accepted; 1.5 by default), showing invisible characters and highlighting trailing whitespace (`color.trailing-space`).
  Preview holds the preview's font size (10 to 32 px, 15 by default) and synced scrolling in split mode (see Split mode).
  General holds the default notebook for new notes.
  The same store also holds Settings > Appearance's sidebar material (see Native look).
  The roomy defaults (line height 1.5, tab size 2, `*` bullets, links for pasted URLs, spell checking on, no active-line highlight) apply only to settings the user never set: Rust writes only the values the user set, so a default that changes later still reaches everything else.
- **Default notebook:** an ID (or none) in the same store, applied by the main window when a note is made while the view shows no notebook (`notebookForNewNote`: the notebook shown, else the default when it still exists, else none).
  The Settings window cannot reach the core, so the main window keeps the notebook names (never note content) in local storage (`notebookChoices.ts`), which the Settings window reads and follows through `storage` events.
- **Store:** a local preference, not note data: Rust keeps it in `<app data>/editor-settings.json` (`src-tauri/src/editor_settings.rs`), outside the notes database, so it never syncs and backups never include it.
  A change is written to a temporary file, flushed to disk and renamed over the old one.
  `editor_settings_get` is granted to every window that draws with the settings (main, note windows, quick capture and Settings), and `editor_settings_set` (a partial change) to the main and Settings windows only; Rust checks every value (booleans, whole-number ranges, fixed lists for the font, weight, indent unit and marker, a short notebook ID or null) and refuses a change with an unknown key or a bad value as a whole.
  Reading the file is lenient: a missing, out-of-range or damaged value takes its default and the rest are kept; the file holds only the values the user set, merged with each change.
  A file that cannot be read (anything but a missing one, such as a permission or I/O error) is never written over, since a change would drop the values it holds: the defaults show, a change is refused with `E_EDITOR_SETTINGS_READ_FAILED`, and the file is read again on the next read or change.
  A damaged file (not a JSON object) is copied to `editor-settings.json.damaged` before the next change replaces it.
  `src/core/editorSettings.ts` holds the same lists, ranges and defaults for the UI.
- **Editor font:** SF Mono by default, nothing bundled.
  Font Family also offers an installed font (`fontFamily: 'installed'`, the family in `installedFont`, listed by AppKit through `fonts_installed`) or an imported file (`'imported'`, the file name in `importedFont`).
  `font_import` (Settings window) asks for a TTF, OTF, WOFF or WOFF2 file in a native panel, checks its extension against its first bytes and its size (50 MB at most), and copies it into `<app data>/fonts/` (a stored file is never replaced: a different file under a taken name is stored as `Name 2.ttf`, so a window never keeps stale glyphs), which never syncs and backups never include; `fonts_list` lists that folder.
  `font_read` returns a stored file's bytes, checked again, and the window loads them as a `FontFace` under one family name of its own (`src/renderer/src/fonts.ts`), so no path or URL reaches the web view.
  Names are checked on both sides (no quotes or backslashes) before they go into the CSS font list, and every list ends with SF Mono, so a font that is missing, invalid or still loading shows SF Mono.
- **Live in every window:** after each change Rust sends `devot://editor-settings-changed` with the full settings and a revision to every window (the Settings window may listen to events for this).
  The revision goes up by one with each stored change, so a window ignores an answer or event older than one it has seen (two changes can announce themselves out of order).
  The page re-sends the event as `devot:editor-settings-changed`, which the UI tests send too.
  A window applies its own changes at once, keeps them on top of what Rust reports until Rust answers (a failed change is dropped), and sends them one at a time, in order.
  Cmd+= and Cmd+- step from the stored size once it has been read.
  The font size field stores a typed size once typing pauses or the field is left.
  Rust was chosen over the webview's local storage because a `storage` event between two WKWebViews is not guaranteed, and a file in Rust gives one validated source of truth.
- **In the editor:** font, size, weight and line height are CSS variables on the root element (`--editor-font-size`, `--editor-font-weight`, `--editor-line-height`, `--editor-font-family`), set through CSSOM, which the CSP allows; the editor's theme reads them, and `--preview-scale` (the preview's font size over the type scale's preview size) scales the preview's text, headings and notes (exported and printed pages leave the variable unset: scale 1).
  Everything else lives in CodeMirror compartments (`src/renderer/src/editor/settings.ts`, the basic setup with those parts split out): a change reconfigures only the parts it touches, so the open editor keeps its text, selection, undo history and focus.
  The gutter (line numbers and folding) goes with Line Numbers; the selection toolbar is off through a facet the toolbar checks (`toolbarOff`); Scroll Past End pads half a screen under the last line (the host element scrolls, not CodeMirror's scroller); the cursor scroll margin is a `scrollMargins` extension; invisible characters and trailing whitespace use CodeMirror's `highlightWhitespace` and `highlightTrailingWhitespace`; the readable width applies only to wrapped lines (the Settings window disables it, with a hint, while lines do not wrap) and not in split mode, where the editor and the preview take half the note area each; popups in the editor keep the UI's font size.
  The list marker is the bullet a new list item gets (the bulleted and task list formats, and a numbered item turned into a bullet); items that have a bullet keep it, and a new item continued with Return keeps its list's marker, since another marker would start a new list.
- **Images under their lines** (`src/renderer/src/editor/images.ts`): each line that shows images (attachments and `https` images) gets a block below it with those images, from a state field (only decorations from the state may change the editor's vertical layout).
  The block has one fixed height (`size.inline-image-height`), known before the images load, so nothing moves as they load or fail.
  An attachment that has not arrived (sync) shows a placeholder box there instead (`src/renderer/src/missingImages.ts`).
  CodeMirror draws only the visible part of a note, so only visible images load; finding images scans the text for `![` and asks the syntax tree only there, so long notes stay cheap.
  Plain `http` images do not show, as the CSP blocks them.
  Double-click opens the viewer; right-click opens the image menu.
