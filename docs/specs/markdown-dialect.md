# Markdown dialect

Part of the [architecture overview](../architecture.md).
Import and export are in [import-and-export.md](import-and-export.md), the `devot` command in [command-line.md](command-line.md), the folder mirror in [markdown-mirror.md](markdown-mirror.md) and templates in [note-templates.md](note-templates.md).

- CommonMark and GFM: tables, task lists, strikethrough, autolinks, footnotes.
- **Line breaks:** a single newline inside a paragraph shows as a line break in the preview (`src/core/preview/softBreaks.ts`), so the lines read as typed; the HTML, PDF and print pages are the preview's tree and follow it.
  The Markdown source and `.md` exports are unchanged.
- YAML front matter: lines between `---` fences at the very start of a note, closed by the first later line that is `---` (spaces or tabs may follow a fence).
  The preview, import and the editor read it alike (the editor through a Lezer Markdown extension, `src/renderer/src/editor/markdown.ts`): nothing inside it is Markdown (the editor's Markdown helpers, such as pasting a URL as a link or HTML tag completion, are off there), the editor shows it in the secondary and tertiary text colours, and formats leave its lines alone.
  A note that starts with `---` and has no closing fence starts with a thematic break.
- Alerts: `> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]`.
- Math: `$…$` and `$$…$$`.
  Mermaid in fenced code blocks.
  Emoji shortcodes (`:tada:`).
- Inline code that holds only a colour (`#RRGGBB`, `rgb(…)`, `hsl(…)`) renders a swatch.
- Note links: `[title](devot://note/<id>)`.
  Attachments: `![](devot://file/<id>)`.
  Links resolve by ID, so renaming a note never breaks them.
  An attachment belongs to one note (`files.note_id`; see Purging attachments), so a note made from another note's text (Duplicate, New Note from Selection, a note from a template) gets its own copies of the images the text shows: each under a new ID, copied in one write (`files_copy`), with the links changed to the copies' IDs (only the ID; a size preset such as `#half` stays).
  Duplicate and New Note from Selection store the new note already showing the copies (`insertNote` in `src/core/notes.ts`; Duplicate changes only the IDs' characters, as edits to a copy of the source's Yjs state), then copy the files; if they cannot be copied, the new note is trashed and purged and the copy's error is thrown (the window logs its code).
- **Purging is for the Trash:** `note_purge` (`Store::purge_note`) purges only a note in the Trash or one with no title and no body (the empty note a `[[` link made), and refuses any other with `E_NOTE_NOT_TRASHED`, so a renderer bug or a hostile page cannot destroy a live note in one call; the TypeScript adapter and the UI tests' memory adapter refuse the same.
  Every caller trashes first.
  A note restored elsewhere while Delete Permanently was being confirmed is the one way a user meets the refusal: the notice says the note is no longer in the Trash and was not deleted, never the code.
  A purge another device made (`sync_note_purge`, `Store::sync_purge`) is not limited by it.
- **Purging attachments:** purging a note deletes its attachments, except each one that another note, not purged (live or in the Trash), still shows: its Markdown holds the address `devot://file/<id>` as written (in capitals, cut short or only in the title it does not count).
  That one passes to such a note, a live one before one in the Trash, then the smallest ID, in the purge's own transaction, so no attachment is ever left to a purged note.
  A link can reach another note without a copy (cut, copied or dragged Markdown, Paste as Plain Text, the `create_note` tool with a body from `read_note`, a restored version, a duplicate or a note from a template made before those copied their images), and its image keeps working; emptying the Trash deletes only the images no note left shows.
  The Rust store and the TypeScript adapter run one statement (`HAND_OVER_FILES_SQL`, a test compares them); it finds the notes that show an attachment through the search index (a phrase match on the address, then the address checked as written), never by reading every note, and the UI tests' memory adapter follows the same rule.
  The core saves pending edits before it purges, so a link pasted a moment before counts.
  A link only an older version in a note's history shows keeps nothing (history is local and its states are not searched): restoring that version brings back the link, not the image.
  The rule reads only the notes' text, so devices that hold the same notes keep the same attachments; attachment sync (#13) has to follow it.
- **Images:** an image's size preset is the fragment of its URL: `![](devot://file/<id>#small)`, `#half` or `#full`; no fragment is Auto (its own size, no wider than the page).
  Other Markdown tools ignore a fragment when they load an image, so they show it at its own size.
  `src/core/images.ts` reads and writes it (round-trip tests in `tests/core/images.test.ts`); only the destination changes, and a URL with another fragment cannot take a size.
  The preview's `devot.images` renderer turns the preset into a class (Small is `size.image-small` wide, Half and Full half and all of the page) and loads the image without it; it also marks where each `![alt](url)` is in the Markdown (`data-image-from`, `data-image-to`), so the image menu can set a size from the preview (reference images and raw HTML have no destination of their own and get no Size submenu).
  The size is set from the image context menu or the palette (`image.size*` commands, for the image at the cursor or the first on its line), as one editor transaction, after checking the text there is still that image.
- **Pasting and dropping images:** each image goes straight from the page to storage (`src/renderer/src/attachments.ts`) and its link goes in at the cursor or the drop point.
  The page refuses what Rust would refuse (over 10 MiB, not a supported raster image) before sending the bytes.
  An image that cannot be stored (refused as not an image or too large, or the database busy past its timeout) is skipped, logged by code and reported in a notice: how many images could not be added and why.
  The link lands where the image was pasted or dropped, not where the caret is when the file is stored: the place is remembered as a Yjs relative position (`src/renderer/src/editor/anchoredInsert.ts`), which follows every edit made meanwhile (text typed at the place goes after the link) and means the same place in the editor's replica and in the core's document.
  If the note was left meanwhile, `NoteService.insertAt` puts the link into the note at that place (the file is never left without a link); if the note is open again by then, its editor takes the link.
  Only a note deleted meanwhile loses it, and its files go with it.
  The caret moves after the link only if it is still at the place.
- **Image viewer** (`src/renderer/src/ImageViewer.tsx`): double-clicking an image in the preview (or under its line in the editor) opens it in a modal over the whole window, fitted to the window or at its actual size (scrolling when larger; a segmented control or a click on the image switches).
  Tab and Shift+Tab go round every stop of it (Fit, Actual, Close, the scrolling stage) without leaving the dialog, Escape or Close dismisses it, and focus goes back where it was.
  The registry's `image.view` (View Image, no default key) opens it from the palette for the attachment image at the cursor, so it has a keyboard route; the Preview offers no key for it (its images are not focusable).
- Typing `[[` opens note search (full-text, live notes only; the first notes of the list for an empty query) and inserts a standard note link, replacing the `]]` that bracket closing added.
  The popup never opens in code (fenced, indented or inline), HTML, comments, front matter or a link's address (the places the slash menu skips too), nor while the parser has not reached the cursor.
  A lookup runs on every key, so it finds notes as stored (`search` with `flush: false`) and never saves the open note, and an empty query takes only the notes the popup shows.
  Text too short for the search index (under three characters) is looked for in titles only (`shortInTitles`), which the list's index holds, so a keystroke never scans every body; the search field keeps scanning bodies for it.
  Picking "New Note …" closes the popup at once (a second Return cannot make a second note), moves the cursor after the brackets and remembers the `[[query]]` as a range that follows the edits made while the note is made; when the note exists, exactly that range becomes the link, and text typed before, after or elsewhere is untouched.
  If the brackets were edited meanwhile or the editor was closed, nothing is linked and the new note is deleted again (as New Note from Selection does), so no note is left behind.
  There is no `[[wikilink]]` storage syntax.
- **Link index:** the `links` table (schema v7) holds, per note, every `devot://note/<UUIDv7>` in its Markdown (`noteLinks` in `src/core/links.ts`; the v7 migration backfills with the same rule in SQL).
  Each body write replaces the note's rows in the same transaction, only when the write lands; purging removes them; trashed notes keep theirs.
  A property test checks the table always equals the stored bodies.
- **Backlinks** (Note Info's linked-from list, the phone's note info; `findBacklinks`) read the link index: storage's `listBacklinks` (the Tauri command `note_backlinks`, `BACKLINKS_SQL`, the same statement in the Rust store and the TypeScript adapter, a test compares them) gives the live notes outside Templates that link to the note, never the note itself, most recently updated first (then by ID, as the note list), at most 200 (`MAX_BACKLINKS`), without excerpts.
  It walks the list's covering index in its order, keeping the notes the index has for the note, so it reads no row and stops at a page.
  So a link counts by the rule of the index: the address as written, in lower case and whole; an address in capitals, cut short, only in the title or running on into more ID characters (a longer ID) is no link.
  The phrase search for the address that backlinks were before counted capitals and longer IDs too, and put the notes in rank order; a property test (`backlinks.property.test.ts`) checks that only those cases differ.
- A video URL alone on its own line renders as an embedded player.
- **Editor commands**: Insert Horizontal Rule (Shift+Cmd+H) is a format command (`src/renderer/src/editor/rule.ts`, in the Format menu after the alerts): it puts `---` on a line of its own after the line with the cursor (the line a selection ends on, whose text stays), with a blank line before it so the text above never becomes a setext heading, and the cursor on a new line under it; a blank line, an empty list item or an empty heading takes the rule itself (a setext underline stays).
  In a quote it keeps the quote markers; in a table or a setext heading it goes after the block; in code, HTML and front matter it does nothing.
  A rule that would be the note's first line, or could close a `---` the note starts with, is `***`, since `---` there would make front matter.
  New Note from Selection (the palette, while text is selected) moves the selected text into a new note in the open note's notebook (none when that notebook was deleted), titled after its first line with text (code fences, rules and setext underlines skipped), without quote, list, task or heading markers (`src/core/extract.ts`, `NoteService.extract`: the body goes in as Yjs operations and the note is stored with it in one write, never empty; images the text shows become the new note's own copies under new IDs (`files_copy`), since purging a note deletes its attachments, and the source keeps its files, so undo there shows its images again), and leaves a note link to it in its place, as one undo step; the open note stays open.
  Undo puts the text back but keeps the new note (undo reverts edits to the open note only).
  A selection that starts or ends inside code, an HTML block or front matter is not offered (a whole block may be selected): a link there would be plain text.
  The range is tracked through edits made while the note is created (`src/renderer/src/editor/extract.ts`); if the selected text itself was edited meanwhile, or another note was opened, the text stays and the new note is deleted again.
  Paste as Plain Text (Shift+Opt+Cmd+V, and the palette) inserts the clipboard's text as it is: no link, no image, no autolink.
  It reads the clipboard through Rust (`clipboard_read_text`): WebKit lets a page read the clipboard only during a key press in the page and then shows its own Paste button, and the palette runs commands after its own keys.
- **Context menus in the note**: a right-click in the editor text (or Shift+F10 / the Menu key at the caret) shows a native menu (`editor/editorMenu.ts`, shown by Rust: `editor_menu_popup`, `editor/systemMenu.ts`): Open Link and Copy Link Address on a link (`linkAt`), Look Up, New Note from Selection and an Edit with AI submenu (see AI > Edit with AI) with a selection, Undo and Redo (CodeMirror's history), the system's Cut, Copy, Paste and Select All (which act on the web view), Paste as Plain Text and a Speech submenu.
  The page lays the menu out as for any context menu and sends it to Rust with the word at the point (`spellingWordAt`; none when a selection is something else), which builds an NSMenu in `native/macos.rs`, waits until it closes and answers with what was picked.
  Rust adds what the Tauri menu API cannot hold: the system's guesses when that word is misspelled (`NSSpellChecker`; a guess picked replaces the word as one undo step) and Learn Spelling, then Writing Tools (`NSMenuItem.writingToolsItems`), Spelling and Grammar (Show Spelling and Grammar, Check Document Now, Check Spelling While Typing, Check Grammar With Spelling, Correct Spelling Automatically) and Services (the app's Services menu for as long as the menu is open).
  Those items have no target: AppKit sends them to the web view and enables and checks them as in its own menus.
  Off macOS (the web view's user agent says so) the Tauri menu API shows the page's items alone.
  The app's own Services menu comes back through a drop guard, also when AppKit throws, and Writing Tools is added only when `NSMenuItem` answers `writingToolsItems`.
  A harness test builds the menu on the main thread and checks the guesses, keys, system items and that a pick arrives.
  A right-click outside the selection moves the caret there first.
  The preview has its own (`preview/previewMenu.ts`: Copy Link Address on https and note links, Look Up, Copy, Select All limited to the preview, Speech; images keep the image menu).
  Look Up and Speech are Rust commands (`text_look_up`, `text_speak` in `native/macos.rs`): Look Up shows the system dictionary for a word at the pointer, Speech speaks the selected text the page sends with a speech synthesizer (the editor draws only the lines near the view, so the web view's own selection can hold a fraction of a long one), uses the web view's own `startSpeaking:` only when the page sends none, and stops both (`stopSpeaking:`); each selector is checked with `respondsToSelector:` and a harness test checks them on a real web view.
  A tag chip and the notebook label in the note header have menus too (`headerMenus.ts`): Tag Settings, Remove Tag, Filter by Tag, Copy Tag ID; Open Notebook (also the command `note.showNotebook`) and Copy Notebook ID.
  WebKit's own Inspect Element is not offered.
- **Pasting URLs** (`src/renderer/src/editor/paste.ts`; the Markdown language's own paste-as-link is off, so a paste is handled once): a URL (`https:`, `http:`, `mailto:`, `devot:` such as a copied note URI, or `www.` given `https://`) pasted over selected text makes the text a link to it, the way Option+Cmd+K links it (line by line, widened over syntax it would cut through, lone brackets escaped; in the address `|`, which would end a table cell, `\`, which would escape the next character, and unpaired parentheses are percent-encoded), the cursor after the link; over a link, a selected address, code or front matter it replaces the text as usual.
  A lone URL (nothing selected) goes in as Settings > Editing > Paste URL as Link says: as copied, as an autolink `<url>`, or as a link with empty text `[](url)` with the cursor in its text; inside code, front matter, a link or an autolink it goes in as copied.
- **Formatting:** selecting text shows a toolbar above it (below when there is no room), and each format has a shortcut.
  Every format is a named command in `src/renderer/src/editor/formats.ts` that turns the editor state into one transaction (one Yjs update, one undo step) editing the Markdown source: bold `**`, italic `*`, strikethrough `~~`, highlight `<mark>` (`==text==` typed by hand reads as a highlight too, in the editor and the preview alike, by strikethrough's flanking rule; the format writes `<mark>`), inline code, links and ATX headings (a setext heading becomes an ATX one, or a paragraph, without its underline).
  Applying a format the whole selection already has removes it; a multi-line selection is formatted line by line, after block markers, leaving code blocks, thematic breaks, HTML blocks, front matter and table delimiter rows alone (table rows are formatted cell by cell).
  New markers and links widen over syntax they would cut through, and marker characters or lone brackets inside them are escaped.
  At a cursor, a format inserts an empty pair to type into, except where the pair would make block syntax (`~~~~` opens a fence, `****` is a thematic break); there it does nothing, as it does at a cursor in code (a blank line of a code block included).
  A command does nothing while the parser has not reached the selection.
  The toolbar works out its pressed buttons again on every selection change, so it reads at most 300 lines of selection (all ranges together; `TOOLBAR_MAX_LINES`): a longer selection shows no button as pressed except Heading, and the commands still act on the whole selection.
  Emphasis, strong and strikethrough markers must flank their text (CommonMark's rule: a marker next to punctuation opens or closes only against white space or punctuation on its other side, and CJK prose has no spaces), so punctuation at the selection's edges that would keep them from parsing goes outside them (an ideographic full stop selected with the text before it stays outside: `XX**YY**<stop>ZZ`; `a **word**.b`).
  Markers are written only where the editor's parser (Lezer, which counts every symbol as punctuation) and the preview's (micromark, which counts ASCII punctuation and Unicode punctuation) read them alike (both read the one UTF-16 unit beside a marker, so an emoji or other character outside the BMP is never punctuation to them); a selection of nothing but such punctuation is left as it is.
  The selection keeps the punctuation, and the same key on it takes the format off again.
  Inline formats, headings and links leave an alert's `> [!KIND]` header line alone, and a link made right after `!` escapes the bang (`\!`), which would otherwise turn it into an image.
  The formats take only the quote and list markers the parser has as the start of a line's text: `2020.` or `3)` on the second line of a wrapped paragraph is text (it is no list item in CommonMark), so a list or heading format keeps it (as an item's text it is escaped, `2020\.`, so it is not read as a nested list).
  Headings go after list markers; task items do not take headings.
  Bracketed text that is not a link (`[draft]`, `[[Note]]`) is wrapped like other text, never unlinked; image text takes no link.
  Block formats (`src/renderer/src/editor/blocks.ts`) act on every line the selection touches, after the line's quote markers: a code block wraps the lines in a backtick fence longer than any fence among them (inside their shared quote, or at the text of the list item they continue); in an empty list item (`2. `, from Shift+Cmd+C) the fence goes after the marker and its lines are lined up with the item's text (`2. ` + three backticks), under the box of an empty task item, and on an indented blank line at the column of the item it continues and unwraps the fenced block a selection is in; bulleted (`- `), numbered and task (`- [ ] `) lists toggle, and switching kinds converts the markers; quotes toggle `> `; alerts add a `> [!KIND]` line (the toolbar's Alert pop-up picks Note, Tip, Important, Warning or Caution) and are changed or removed as a whole block.
  When a marker gets wider or narrower, the lines under its item move with it, so nesting is kept; numbered lists that gain an item are renumbered from their first number, and the items after one that leaves a numbered list count from 1 again, in the same step.
  Only the selected lines change; a line next to them may still read as the lazy continuation of the block above, as Markdown has it.
  Lines of fenced code, tables, rules and HTML blocks are left alone, and front matter by every block format, the code block included; lists also skip setext headings and lines that continue an item (unless only those are selected).
  A line that continues a list item is quoted inside that item, unless the item's own line is selected too; a list item is quoted with its children and a setext heading whole.
  Lines of fenced code inside a quote are code too.
  Code blocks wrap each range of a multiple selection on its own and take in the whole of a fenced block the selection cuts into.
  Shift+Cmd+C makes a code block in the editor and copies a note's URI on a note list row; each area handles only its own keys.
  The toolbar, the shortcuts, the menu bar's Format menu, the command palette and the slash menu run these commands.
  Their keys come from the command registry (see Commands and shortcuts).
- **Return in lists and quotes** (`src/renderer/src/editor/enter.ts`, ahead of the Markdown language's own Return): Return on an empty list item (including the second item of a two-item list, which the language's Return would turn into a loose list) or on an empty quote or alert line leaves it with one blank line between it and the cursor, so text typed there is a paragraph of its own (without the blank line it would continue the last item lazily); a nested list or quote goes out one level (the outer quote's or item's markers stay).
  With no line of text above, or a blank one, the marker only goes.
  On an empty quote line in the middle of a quote (a line of the quote follows, also when the line is in a list in the quote), or in a code block in a quote, Return continues the quote instead (keeping the indent typed after its markers), so it is never split in two; a quote that opens a list item (`- > `) is left for the empty item (`- `).
  Markers are read from the syntax tree with the scan the formats use (`lineMarks.ts`).
  It is one transaction and one undo step.
- **Slash menu:** typing `/` at column 0 of a line opens a list at the cursor (`src/renderer/src/editor/slashMenu.ts`) in three groups, each with a small header that scrolls with the list: Basic Formatting (Blockquote, Codeblock, Heading 1 to 4, Horizontal Rule, Image File, Link, Ordered List, Remote Image, Task List, Unordered List), Alerts (Caution, Important, Note, Tip, Warning, each icon in its alert colour) and Other (Note Link).
  Each row shows an icon, the label and, on the right, the Markdown it writes.
  Most items are registry commands (a format above, or an insertion from `src/renderer/src/editor/insert.ts`); Remote Image writes `![alt](url)` as a snippet (Tab goes from `alt` to `url`), Image File takes the query out and opens the system file panel for images, stored as a pasted image is, and Note Link puts `[[]]` there and opens the `[[` note popup.
  Table is a palette command only.
  The text typed after the slash filters the list: a case-insensitive substring of the label, ordered by where it matches, then by the menu's order (`ist` gives Task List, Ordered List, Unordered List); the matched letters are bold.
  An item whose command would do nothing there or take a format off is left out.
  Up and Down wrap around.
  Return picks: the `/query` goes and the command runs in its place, as one transaction and one undo step.
  A query that matches nothing closes the list, and that slash does not open it again (Backspace included); nor does Escape's or a lost focus's.
  It never opens with several cursors or a selection, nor in code, HTML, comments, front matter, or a link's address.
  The empty line holding the cursor shows `Type '/' for commands...` as ghost text (drawn by CSS, not text of the note), and an empty note shows a chip that runs New Note from Template.
  The same popup style serves the `[[` note popup, `:` plus two or more word characters (emoji shortcodes; picking one inserts the emoji) and `> [!` (the alert kinds).
  While an input method composes, no list opens, and keys of a composition never reach an open list (WebKit may report the Return that ends one, key code 229, after it has ended).
  The popups, their sources and the editing aids around them are put together in `src/renderer/src/editor/completions.ts`.
- **Code blocks in the editor** (`src/renderer/src/editor/codeBlocks.ts`): every line of a fenced block, its fences included, sits in one box (line decorations; an unclosed fence boxes the rest of the note, as the parser reads it); the fence takes the markup colour and its info string the heading colour.
  The box's own background carries the active line's tint, so it keeps to the box's rounded edges and its margins; while text is selected, the selection's tint stands instead.
  The editor pads both sides of a line equally, and that padding is the note's text column.
  A code block's box and a table's sit on that column, with the text inside set further in, so the box lines up with the prose.
  CodeMirror's full rows stop at the first line's padding; a row that stops inside the box grows out to the column, and a short first or last row reaches the rest of the way (`editor/selectionEdges.ts`), so the tint wraps the box and lines up across formats.
  A quote's bar is drawn in the line's border and shifted out to that same column, so a quote keeps every line's padding and does not shift the selection's width.
  While the selection is in a block that is not in a quote or alert, a copy button in the box's top-right corner copies the code without its fences (and without the indentation of a list item's block).
  On an opening fence line, right after the fence, a list offers every alias `@codemirror/language-data` knows with the language's name, filtered fuzzily; picking one writes it after the fence and keeps the cursor there.
  Code Block on a blank line (from the slash menu, the toolbar or its key) writes the fences around an empty line, puts the cursor after the opening fence and opens that list; a fence typed by hand opens nothing and gets no closing fence.
  In a block, Tab inserts the indent unit and Return starts a line with the block's quote or list prefix and the indent its language gives (`src/renderer/src/editor/codeIndent.ts`): the line's own, a level in after what opens one (a bracket; a trailing colon in Python and YAML; `do`, `then` and block keywords in Ruby, Lua and shell; an open tag in HTML and XML), a level out after `return`, `pass`, `break`, `continue` or `raise` in Python; between a pair (brackets, tags) the closing one goes to a line of its own.
  The indent unit (Return and Tab) is the block's own when its lines are indented, else its language's convention (a tab for Go and Makefiles, four spaces for Python, Rust, Java, Kotlin, C, C++, C#, Swift, PHP), else the editor's.
- **Tables:** while the cursor is in a GFM table, Tab and Shift+Tab go to the end of the next and previous cell (Tab in the last cell adds a row), Return goes to the same column of the next row (to its first cell after a row's closing pipe; adding a row at the end; on an empty last row it removes that row and leaves the table below a blank line; before a row's first character it opens a line above the row as elsewhere, so a table at the top of a note can get a line before it), Option+Return inserts a row below, and Option+Up and Option+Down move the row.
  Outside a table, with several cursors, or with a selection over several lines, these keys do what they do elsewhere in the editor (Tab indents the line, Shift+Tab outdents it; Control+Tab leaves the editor, see Keyboard navigation).
  The command palette offers, while the cursor is in a table, inserting, deleting and moving rows and columns, setting a column's alignment (left, center, right, none) and Format Table.
  The model (`src/renderer/src/editor/table.ts`) reads the table as GFM does: cells are trimmed of spaces and tabs only (U+3000 and U+00A0 are cell text), a pipe ends a cell unless a backslash escapes it, also inside a code span, outer pipes are optional, and ragged rows are padded with empty cells (no cell is dropped).
  Every table command and key prints the whole table formatted (outer pipes, columns padded to their widest cell by display width, wide East Asian characters and emoji counting two, cells placed by their alignment, the delimiter row keeping its markers) as one transaction, one undo step, like the formats (`src/renderer/src/editor/tableCommands.ts`); a table in a quote or a list keeps each line's markers.
  A row can also be typed by hand (`src/renderer/src/editor/tableTyping.ts`): on an empty row that Tab, Return or Insert Row left the cursor in, and while the cursor stays on that row, the first pipe typed is the row's opening pipe (the cursor goes to the first cell), a pipe typed at the end of a cell's text or in an empty cell goes to the next cell (from the last cell, past the closing pipe) and formats the table, and a space typed right after such a pipe is dropped as padding; so `| 1 | 2 |` typed after Return fills two cells.
  A pipe inside a cell's text, after a backslash or after the closing pipe, input during IME composition or with the completion list open, and every other row are typed as written.
  Each cell's typing and the pipe that ends it are one undo step (the padding a pipe removes is taken next to the cursor, so its change joins the typing).
  Changes from elsewhere (sync) keep the row being typed.
- Import keeps the source text as-is, except image destinations and wiki-style links.
  Unless the import sheet's checkbox is cleared, `[[Title]]`, `[[folder/Title#Heading|Shown]]` and `![[image.png|300]]` become note links and attachments once every note exists: a note of that file name or title in the import, else of that title in the library (case and diacritics aside), and an image of that name in the folder, at the nearest size preset.
  Links in code stay.
  A link nothing matches stays as written and the summary counts it.
